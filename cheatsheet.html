Замыкание (Closure) Day 2

Функция «запоминает» переменные из внешней области видимости даже после того, как та завершила выполнение.

function createIdGenerator() {
  let id = 1; // скрытая переменная

  return function() {
    return id++; // доступ к id через замыкание
  };
}

const nextId = createIdGenerator();
nextId(); // 1
nextId(); // 2  ← id изолирован!

Применение: счётчики шагов, изолированные логгеры, генераторы тестовых данных, инкапсуляция.

Определение this Day 3

1. Вызов с new? → this = новый объект 2. .call/.apply/.bind? → this = явно переданный объект 3. Метод объекта (obj.fn())? → this = obj 4. Стрелочная функция? → this = из родителя (Lexical) 5. Иначе: strict → this = undefined sloppy → this = global

Ловушка: передача метода как коллбека — this теряется!

await test.step("...", page.fill); // ❌ потеря this
await test.step("...", () => page.fill()); // ✅
await test.step("...", page.fill.bind(page)); // ✅

⚠️ Все методы — поверхностные (shallow). Вложенные объекты не заморожены!

// Deep Freeze (рекурсивно):
function deepFreeze(obj) {
  Object.keys(obj).forEach(k => {
    if (typeof obj[k] === 'object') deepFreeze(obj[k]);
  });
  return Object.freeze(obj);
}

В строгом режиме ("use strict") попытка изменить → TypeError.

Object, Array, Tuple + interface vs type

// Объектный тип (inline):
const res: { status: string; code: number }
           = { status: 'ok', code: 200 };

// interface — для объектов / классов:
interface ApiResponse {
  status: string;
  data:   unknown;
  code?:  number;  // ? = необязательное поле
}

// type — мощнее (union, intersection, literal):
type Selector = string;
type Env = 'local' | 'staging' | 'prod';

// Массив (два эквивалентных синтаксиса):
const sels: string[]       = ['#btn', '.link'];
const nums: Array<number>  = [1, 2, 3];

// Кортеж — фиксированная длина + типы позиций:
type TestRow = [string, number, boolean];
const row: TestRow = ['Login test', 3, true];
// row[0] → string ✅   row[3] = 'x' → Error!

interface → для Page Objects и форм данных. type → для union, literal, utility types.

any vs unknown vs void vs never Ключевые типы

ТипЗначениеПрисвоить что угодно?Использовать без проверки?

any в тестах — грубейший антипаттерн! Отключает все проверки TS. Используй unknown + narrowing.

// any — ❌ антипаттерн:
function parse(data: any) {
  data.nonExistentMethod(); // TS молчит → Runtime Error!
}
// unknown + narrowing — ✅:
function handle(data: unknown) {
  if (typeof data === 'object' && data !== null
      && 'status' in data) {
    console.log((data as {status: string}).status);
  }
}
// void — функция-действие Page Object:
async function clickLogin(): Promise<void> {
  await page.click('#login-btn');
  // return → тип void ✅
}

// never — хелпер ассертов:
function assertNever(val: never): never {
  throw new Error(`Unexpected: ${val}`);
}

Advanced Types Union · Intersection · Literal

// Union — «либо-либо»:
type UserId = string | number;  // ID из разных источников
type Status = 'pass' | 'fail' | 'skip';

// Literal — ограничить точными значениями:
const env: 'local' | 'staging' | 'prod' = 'staging';

// Intersection — «должен иметь всё»:
type Admin = User & { role: 'admin'; perms: string[] };

// Nullable — явное разрешение пустоты:
type MaybeUser = User | null | undefined;

// Non-null assertion ! — «я знаю, что не null»:
const el = document.getElementById('btn')!; // осторожно!

// Optional chaining + TypeScript:
const city = user?.address?.city; // тип: string | undefined

Literal types — лучший способ типизировать окружения, статусы, режимы. IDE сама подскажет допустимые значения.

Type Guards + Narrowing

Narrowing — сужение типа через проверку. Обязательно при unknown и union-типах.

// typeof narrowing:
function process(val: string | number) {
  if (typeof val === 'string') {
    val.toUpperCase(); // TS: string ✅
  } else {
    val.toFixed(2);    // TS: number ✅
  }
}

// instanceof narrowing:
if (err instanceof Error) {
  console.log(err.message); // TS: Error ✅
}

// in narrowing (для object):
if ('code' in response) {
  response.code; // TS: есть поле code ✅
}

// Пользовательский type guard:
function isApiError(e: unknown): e is ApiError {
  return typeof e === 'object' && e !== null
         && 'code' in e && 'message' in e;
}

if (isApiError(err)) {
  err.code;    // TS: ApiError ✅
}

tsconfig.json — эталонный конфиг для AQA

{
  "compilerOptions": {
    // Окружение:
    "target":               "ES2022",     // JS-стандарт на выходе (Node.js 18+)
    "module":               "NodeNext",   // ESM: import/export
    "moduleResolution":     "NodeNext",   // Как ищет библиотеки
    "lib":                  ["ES2022", "DOM"], // Типы JS + DOM-браузера

    // Строгость (рекомендовано включить всё):
    "strict":               true,         // Максимальная строгость (включает 8+ проверок)
    "noImplicitAny":        true,         // Запрет неявного any
    "strictNullChecks":     true,         // Проверка null/undefined перед использованием

    // Совместимость:
    "esModuleInterop":      true,         // CJS как ESM: import lodash from 'lodash'
    "resolveJsonModule":    true,         // import data from './fixture.json' + автодополнение
    "skipLibCheck":         true,         // Не проверять node_modules → +80% скорость
    "forceConsistentCasingInFileNames": true, // Защита Mac/Linux/Win регистра

    // Сборка:
    "noEmit":               true          // Не писать .js на диск (раннеры = in-memory)
  },
  "include": ["src/**/*.ts", "tests/**/*.ts"],
  "exclude": ["node_modules"]
}
