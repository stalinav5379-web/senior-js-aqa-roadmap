Сегодня мы разберем две важнейшие концепции JavaScript, которые напрямую влияют на стабильность ваших тест-кейсов и архитектуру тестовых фреймворков.

## 1. Обычные функции (`function() {}`) vs Стрелочные функции (`() => {}`)

На первый взгляд, стрелочные функции — это просто красивый сокращенный синтаксис (синтаксический сахар), появившийся в ES6. Однако под капотом кроется фундаментальное различие в работе с контекстом выполнения **`this`**.

### А. Разница в поведении `this`
*   **Обычная функция** динамически определяет `this` в момент своего вызова. Значение `this` зависит исключительно от того, *кто* и *как* вызвал эту функцию.
*   **Стрелочная функция** не имеет собственного контекста `this`. Она заимствует его из внешнего окружения (лексического контекста), в котором была объявлена. Это поведение нельзя изменить даже методами `.bind()`, `.call()` или `.apply()`.

### Б. Почему это критично для QA Automation?

#### 1. Использование алиасов и контекста в Cypress + Mocha
Фреймворк Cypress использует Mocha под капотом. Mocha автоматически связывает контекст `this` с текущим тестом, позволяя делиться данными между хуками (`beforeEach`) и тестами (`it`) с помощью механизма алиасов (`.as()`).

*   **Если вы напишете тест через стрелочную функцию, `this` будет равен `undefined` (или ссылаться на глобальный контекст Node.js), и тест упадет с ошибкой.**

```javascript
// ❌ ТАК ДЕЛАТЬ НЕЛЬЗЯ (Cypress + Mocha)
describe('Тестирование профиля пользователя', () => {
  beforeEach(() => {
    cy.fixture('user.json').as('currentUser'); // Создаем алиас
  });

  // Стрелочная функция сломает контекст:
  it('проверяет имя пользователя в системе', () => {
    // ❌ Ошибка! TypeError: Cannot read properties of undefined (reading 'currentUser')
    cy.get('#welcome-title').should('have.text', this.currentUser.name); 
  });
});
Для корректной работы контекста Mocha используйте только обычную функцию:
javascript


// ✅ ПРАВИЛЬНЫЙ ВАРИАНТ
describe('Тестирование профиля пользователя', () => {
  beforeEach(() => {
    cy.fixture('user.json').as('currentUser');
  });

  // Обычная функция сохраняет контекст Mocha:
  it('проверяет имя пользователя в системе', function() { 
    cy.get('#welcome-title').should('have.text', this.currentUser.name); // Всё работает!
  });
});
Примечание для Playwright: Playwright не использует this для проброса данных между хуками (там для этого используются Fixtures), поэтому в Playwright принято писать тесты через лаконичные стрелочные функции: test('test name', async ({ page }) => { ... }).

📘 Дополнение к Дню 2: Глубокое погружение в Arrow vs Regular Functions
Для создания красивой документации вы можете сохранить этот файл как day2_functions_deep_dive.md.

1. Четыре главных отличия Regular от Arrow Functions
Помимо синтаксиса, между ними есть 4 глубоких архитектурных различия:

1. Контекст this (Execution Context)
Regular Function: имеет свой собственный this [1, 2]. Он определяется динамически в момент вызова функции [1, 2].
Если функция вызвана как метод объекта (obj.method()), то this равен этому объекту [1, 2].
Если функция вызвана просто так (func()), то в обычном режиме this будет равен глобальному объекту (window / global), а в строгом режиме ("use strict") this будет равен undefined.
Arrow Function: не имеет своего this [1, 2]. Она заимствует его из внешнего окружения в момент своего создания (лексический контекст) [1, 2]. Изменить его с помощью .bind(), .call() или .apply() невозможно [1, 2].
2. Конструкторы (Конструкция new)
Regular Function: может быть вызвана с ключевым словом new (служит конструктором для создания объектов). У нее есть свойство prototype.
Arrow Function: не может быть конструктором [2]. При попытке написать new MyArrowFunc() JS выбросит ошибку: TypeError: MyArrowFunc is not a constructor. У нее также нет свойства prototype.
3. Объект аргументов (arguments)
Regular Function: внутри нее доступен специальный локальный псевдомассив arguments, содержащий все переданные в функцию параметры.
Arrow Function: не имеет объекта arguments. Если вам нужно собрать все параметры в стрелочной функции, необходимо использовать современный ES6 rest-оператор ...args.
javascript


// Regular Function
function showArgs() {
  console.log(arguments); // [Arguments] { '0': 'AQA', '1': 'JS' }
}

// Arrow Function
const showArgsArrow = (...args) => {
  console.log(args); // ['AQA', 'JS'] (настоящий массив)
};
4. Дублирование параметров
Regular Function: разрешает дублирование имен параметров в нестрогом режиме (например, function sum(a, a) {} — хотя это и плохой тон).
Arrow Function: никогда не разрешает дублирование параметров, это всегда вызывает синтаксическую ошибку (SyntaxError).

2. Замыкание (Closure) — Скрытая суперсила JS
Замыкание (Closure) — это комбинация функции и лексического окружения, в котором эта функция была определена. Простыми словами: замыкание позволяет функции запоминать переменные из внешней области видимости и иметь к ним доступ даже после того, как внешняя функция завершила свое выполнение.

Зачем это нужно Senior AQA?
Замыкания активно используются для инкапсуляции данных (скрытия переменных от прямого изменения извне), создания изолированных генераторов тестовых данных, логгеров, счетчиков шагов и кастомных ассертов.

Практический пример: Изолированный генератор тестовых ID
Представьте, что при генерации пользователей для автотестов вам нужно гарантировать, что каждый новый пользователь получит уникальный порядковый ID, но вы не хотите делать переменную id глобальной, чтобы другие тесты случайно её не перезаписали.

javascript


function createIdGenerator() {
  let id = 1; // Закрытая переменная внутри области видимости createIdGenerator()

  return function() {
    // Внутренняя функция имеет доступ к переменной id благодаря замыканию
    return id++; 
  };
}

// createIdGenerator завершила работу, но переменная id осталась в памяти,
// так как на нее ссылается возвращенная функция:
const generateUserId = createIdGenerator(); 

console.log(generateUserId()); // Выведет: 1
console.log(generateUserId()); // Выведет: 2
console.log(generateUserId()); // Выведет: 3

// Никакой другой тест не может залезть в память и написать id = "сломано",
// данные полностью изолированы и безопасны!

Эта функция должна создавать изолированный логгер для каждого теста. Логгер должен:
Хранить внутри себя счетчик шагов (начиная с 1).
Хранить время создания логгера (метку времени).
При каждом вызове выводить: [Шаг X] [Прошло Y мс с начала теста] -> Ваше сообщение.
Шаблон кода для day2.js (Скопируйте и допишите):
javascript


"use strict";

function createTestLogger(testName) {
  const startTime = Date.now(); // Время старта теста
  let stepCount = 1;            // Счетчик шагов (скрытый внутри замыкания)

  // ВЕРНИТЕ функцию, которая принимает сообщение шага (например, "Клик по кнопке")
  // И выводит лог в консоль, увеличивая шаг на 1.
  return function(stepMessage) {
    const elapsed = Date.now() - startTime;
    console.log(`[Тест: ${testName}] [Шаг ${stepCount}] [+${elapsed}мс] -> ${stepMessage}`);
    stepCount++;
  };
}

// === ПРОВЕРКА РАБОТЫ ===

// Создаем независимый логгер для Теста Авторизации
const logAuthTest = createTestLogger("Авторизация");

logAuthTest("Открытие страницы логина"); 
// Должно вывести примерно: [Тест: Авторизация] [Шаг 1] [+0мс] -> Открытие страницы логина

setTimeout(() => {
  logAuthTest("Ввод логина и пароля");
  // Должно вывести примерно: [Тест: Авторизация] [Шаг 2] [+100мс] -> Ввод логина и пароля
}, 100);

setTimeout(() => {
  logAuthTest("Нажатие кнопки Войти");
  // Должно вывести примерно: [Тест: Авторизация] [Шаг 3] [+250мс] -> Нажатие кнопки Войти
}, 250);

// Имитируем параллельный запуск другого теста!
// Его счетчик шагов и время должны быть полностью изолированы.
setTimeout(() => {
  const logCartTest = createTestLogger("Корзина");
  logCartTest("Добавление товара в корзину");
  // Должно вывести: [Тест: Корзина] [Шаг 1] [+0мс] -> Добавление товара в корзину
}, 150);

javascript


"use strict";

// Имитируем браузерное окружение для теста
const browser = {
  clickElement(selector) {
    console.log(`🌐 [Браузер] Клик по элементу на странице: ${selector}`);
  }
};

// === КЛАСС, КОТОРЫЙ НУЖНО ИСПРАВИТЬ ===
class Button {
  constructor(name, selector) {
    this.name = name;
    this.selector = selector;
  }

  // Данный метод сейчас написан как Regular Function.
  // При передаче в качестве коллбека он теряет свой 'this'.
  click() {
    console.log(`🖱️ [Фреймворк] Попытка кликнуть по кнопке: "${this.name}"`);
    browser.clickElement(this.selector);
  }
}

// === СЕНАРИЙ ИСПОЛЬЗОВАНИЯ (Симулируем работу тест-раннера) ===

const loginButton = new Button("Войти", "#submit-login-btn");

// Имитируем тест-раннер, который принимает функцию-шаг и запускает её асинхронно
function runTestStep(stepCallback) {
  console.log("🏃‍♂️ [Тест-раннер] Запуск шага теста...");
  try {
    stepCallback(); // Запуск переданного коллбека
  } catch (error) {
    console.log("💥 [Тест-раннер] Шаг упал с ошибкой!");
    console.log(error.message);
  }
}

// Передаем метод клика в тест-раннер как ссылку на функцию (коллбек)
runTestStep(loginButton.click);
