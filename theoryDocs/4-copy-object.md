# 📘 День 4: Объекты в памяти, Копирование (Shallow vs Deep) и Ограничение изменений (`freeze`, `seal`)

Сегодня мы изучим, как JavaScript работает с памятью на низком уровне, и как эти знания уберегут нас от коварных «багов-призраков» в тест-фреймворках (когда один тест незаметно меняет данные другого).

---

## 1. Распределение памяти: Стек (Stack) vs Куча (Heap)

Движок JavaScript разделяет оперативную память на две ключевые структуры: **Стек (Stack)** и **Кучу (Heap)**.
[ CALL STACK ] (Быстрый, фиксированный) [ MEMORY HEAP ] (Динамическая куча)
┌─────────────────────────────────┐ ┌────────────────────────────────┐
│ name: "Alice" (Primitive) │ │ │
├─────────────────────────────────┤ │ { │
│ userRef: 0x8F2A0 ───────────────┼─────────►│ role: "Admin", │
└─────────────────────────────────┘ │ permissions: ["read"] │
│ } │
└────────────────────────────────┘

### Стек (Call Stack)

- Предназначен для хранения **примитивных типов данных** (Primitive Types: `string`, `number`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) и **ссылок/указателей** (Pointers) на объекты.
- Работает невероятно быстро, память очищается автоматически при завершении контекста выполнения.

### Куча (Memory Heap)

- Предназначена для хранения **ссылочных типов данных** (Reference Types: `object`, `array`, `function`, `Map`, `Set`).
- Память выделяется динамически, размер объектов может расти.
- В стеке сохраняется лишь короткий **шестнадцатеричный адрес (ссылка)**, указывающий на фактическое место в куче, где лежит сам объект.

---

## 2. Копирование по Значению (By Value) vs по Ссылке (By Reference)

### Копирование по значению (Primitives)

При копировании примитива JavaScript создает абсолютно независимую копию значения в стеке.

```javascript
let original = "A";
let copy = original; // Копирует само значение "A" в стеке
copy = "B";

console.log(original); // "A" (Исходное значение не изменилось!)
Копирование по ссылке (Objects)
При копировании объекта копируется только ссылка (указатель) из стека, но не сам объект из кучи. Оба значения начинают смотреть на один и тот же адрес.

javascript


const originalObj = { name: "Alice" };
const copyObj = originalObj; // Скопирована только ссылка!

copyObj.name = "Bob"; // Изменили объект по ссылке

console.log(originalObj.name); // "Bob" (⚠️ Исходный объект тоже изменился!)
⚠️ Влияние на QA Automation: Если вы храните общий объект тестовых данных (Test Data Fixture) и присваиваете его в тесте локальной переменной напрямую, любое изменение полей этой переменной исказит данные для всех последующих тестов, запущенных параллельно!

3. Клонирование Объектов (Shallow vs Deep Copy)
Чтобы безопасно скопировать объект и разорвать связь с оригиналом, его нужно клонировать.

А. Поверхностное копирование (Shallow Copy)
Копирует только первый уровень ключей. Если внутри объекта есть вложенные объекты или массивы, они копируются по ссылке.

Способ 1: Спред-оператор (Spread Operator ...)
javascript


const user = { name: "Alice", settings: { theme: "dark" } };
const shallowClone = { ...user };
Способ 2: Метод Object.assign()
javascript


const shallowClone = Object.assign({}, user);
Ловушка поверхностного копирования (Shallow Copy Trap):
javascript


shallowClone.name = "Bob";             // Первый уровень скопирован успешно
shallowClone.settings.theme = "light"; // ⚠️ Изменение вложенного объекта изменит и оригинал!

console.log(user.name);            // "Alice" (Безопасно)
console.log(user.settings.theme);  // "light" (⚠️ ОРИГИНАЛ ИСПОРЧЕН!)
Б. Глубокое копирование (Deep Copy / Deep Clone)
Полностью рекурсивно копирует все уровни вложенности объектов, делая копию абсолютно независимой.

Способ 1: Метод structuredClone() (Современный стандарт)
Встроенный нативный метод Node.js (v17+) и современных браузеров. Отлично копирует сложные объекты, массивы, типы Date, Map, Set, RegExp.

javascript


const original = { date: new Date(), nested: { id: 1 } };
const deepClone = structuredClone(original); // Полный глубокий клон!

deepClone.nested.id = 99;
console.log(original.nested.id); // 1 (Оригинал в полной безопасности!)
Ограничение: structuredClone выбросит ошибку, если внутри объекта есть активные функции (методы) или DOM-ноды.
Способ 2: JSON-сериализация (Legacy/Быстрый хак)
javascript


const deepClone = JSON.parse(JSON.stringify(user));
Опасность: Метод "ломает" типы данных. Он превращает объекты Date в обычные строки, полностью удаляет свойства со значением undefined, стирает функции/методы и падает, если в объекте есть циклические ссылки.
4. Ограничение изменений объектов
Для защиты конфигураций фреймворка от случайного изменения тестами или другими инженерами в JS есть три уровня блокировки:
| Метод                      | Можно добавлять новые свойства? | Можно удалять свойства? | Можно менять значения существующих? |
| :-- | :-- | :-- | :-- |
| Object.preventExtensions() | ❌ Нет                           | ✅ Да                   | ✅ Да |
| Object.seal()              | ❌ Нет                           | ❌ Нет                  | ✅ Да |
| Object.freeze()            | ❌ Нет                           | ❌ Нет                  | ❌ Нет |

1. Object.preventExtensions() (Запрет расширения)
Запрещает добавлять новые свойства. Существующие свойства можно редактировать и удалять.

2. Object.seal() (Опечатывание)
Запрещает добавлять новые свойства и удалять старые. Можно только редактировать существующие значения.

3. Object.freeze() (Замораживание)
Полностью блокирует любые изменения. Объект становится "только для чтения" (Read-Only).

⚠️ Помните про две ловушки:

Все эти методы — поверхностные (shallow). Вложенные объекты внутри замороженного объекта всё еще можно изменять! Чтобы заморозить весь объект глубоко, нужно писать рекурсивную функцию deepFreeze.
В обычном режиме JS попытки изменить замороженный объект будут молча игнорироваться (fail silently). Обязательно используйте строгий режим ("use strict") или TypeScript, чтобы приложение сразу падало с явной ошибкой TypeError.
```

Суть проблемы:
Когда мы пишем автотесты, у нас есть базовый конфиг baseConfig. Мы хотим переопределять только отдельные вложенные поля для конкретного окружения (например, изменить только порт в объекте db, не стирая остальные настройки базы данных) [1.2].

Если использовать обычный Object.assign() или Spread-оператор, они затрут вложенные объекты целиком (это называется Shallow Merge), и мы потеряем все остальные настройки! [1.2]

Ваша задача:
Написать функцию createEnvironmentConfig(envOverrides).
Эта функция должна:

Создать глубокую копию (Deep Copy) baseConfig, используя structuredClone() [1.2].
Написать логику глубокого объединения (Deep Merge) для вложенных объектов db и api [1.2]. То есть, если в envOverrides передан только db: { port: 8080 }, функция должна заменить только порт, но бережно сохранить host и username [1.2]!
Заморозить итоговый объект с помощью Object.freeze(), чтобы его нельзя было случайно сломать во время тестов [1.2].
