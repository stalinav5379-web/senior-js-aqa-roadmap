# 📚 Шпаргалка: Полная система типов в TypeScript (TS Types System)

TypeScript расширяет стандартные типы JavaScript, добавляя строгие статические типы для повышения надежности и удобства разработки. Ниже приведены все типы данных, существующие в TypeScript, разделенные по категориям.

---

## 1. Примитивные типы (Primitive Types)

Простые типы данных, которые соответствуют базовым значениям в JavaScript.

- **`string`** — Текстовые строки (например, `"click"`, `'#id'`).
- **`number`** — Любые числа: целые, дробные, отрицательные, а также `NaN` и `Infinity` (например, `3`, `-0.5`, `3.14`).
- **`boolean`** — Логический тип, принимающий только `true` (истина) или `false` (ложь).
- **`null`** — Явное отсутствие значения переменной.
- **`undefined`** — Неинициализированное значение (переменная объявлена, но ей ничего не присвоено).
- **`symbol`** — Уникальные и неизменяемые идентификаторы объектов (ключи).
- **`bigint`** — Числа произвольной точности, превышающие предел безопасных целых чисел JS ($2^{53} - 1$). Пишутся с суффиксом `n` (например, `9007199254740991n`).

---

## 2. Структурные типы объектов (Structural & Object Types)

Используются для описания сложных составных структур данных.

- **`object`** — Любое не-примитивное значение (всё, что не является числом, строкой, булевом и т.д.).
- **`{}` (Plain Object / Объектный тип)** — Описывает точную структуру объекта с именами полей и их типами (например, `{ name: string; age: number }`).
- **`type[]` / `Array<type>`** — Список (массив) однотипных элементов (например, `string[]` или `Array<number>`).
- **Кортежи (Tuples, `[type1, type2]`)** — Массив фиксированной длины, где для каждого индекса жестко задан свой тип (например, `[string, number]`).

---

## 3. Специальные типы TypeScript (Special Types)

Особые типы, добавленные компилятором TS для обработки динамических данных и крайних состояний.

- **`any`** — **«Аварийный выход»**. Полностью отключает проверку типов. Переменной этого типа можно присвоить что угодно и вызывать у нее любые методы. _Использование any в коде автотестов — грубейший антипаттерн!_
- **`unknown`** — **Безопасная альтернатива `any`**. Означает, что тип данных неизвестен (например, динамический ответ от API). Переменную этого типа нельзя использовать, пока вы явно не проверите её тип (не сузите его).
- **`void`** — Означает **отсутствие возвращаемого значения**. Используется как возвращаемый тип для функций, которые выполняют действия, но ничего не возвращают (например, клик по кнопке в Page Object).
- **`never`** — Тип значений, которые **никогда не могут наступить**. Используется для функций, которые всегда выбрасывают ошибку (throw Error) или уходят в бесконечный цикл.

---

## 4. Сложные и Объединенные типы (Advanced Types)

Позволяют создавать гибкие контракты на основе комбинации других типов.

- **Объединения (Union Types, `A | B`)** — Означает, что переменная может быть либо типа А, либо типа В (например, `string | number` — часто используется для ID).
- **Пересечения (Intersection Types, `A & B`)** — Объединяет несколько типов в один. Объект должен удовлетворять всем объединенным типам одновременно.
- **Литеральные типы (Literal Types)** — Ограничивают переменную строго конкретными значениями (например, `const env: "local" | "staging" | "prod"`).
- **Обнуляемые типы (Nullable Types, `type | null | undefined`)** — Явное указание компилятору, что переменная может быть пустой.

---

## 5. Обобщенные типы (Generics)

Шаблоны типов, позволяющие писать переиспользуемый и гибкий код, сохраняя строгую типизацию.

- **`Type<T>`** — Тип-шаблон, который принимает конкретный тип `T` во время вызова (например, `Promise<string>`, `Record<string, number>`).

---

## 6. Встроенные типы среды выполнения (Built-in Env Types)

Предоставляются TypeScript из коробки на основе библиотек среды выполнения (например, библиотеки `DOM` в вашем `tsconfig.json`).

- **`Date`** — Стандартные объекты дат.
- **`RegExp`** — Объекты регулярных выражений.
- **`Promise<T>`** — Результат выполнения асинхронной операции, которая вернет значение типа `T`.
- **`Error`** — Объект стандартной ошибки (часто используется в блоках `catch (error)`).
- **`HTMLElement` / `Element`** — Нативные DOM-элементы браузера (используются при инъекциях JS-кода в браузер).

## 1. Почему TypeScript — это стандарт в современном AQA?

Обычный JavaScript — это язык с **динамической типизацией** [3]. Он позволяет записать в переменную число, затем заменить его на строку, а затем вызвать несуществующий метод. Вы узнаете о том, что код сломан, только **во время выполнения (Runtime)**, когда ваш автотест уже упадет посреди CI/CD пайплайна [1.3].

**TypeScript (TS)** добавляет к JavaScript **статическую типизацию (Static Typing)** [1.3]. Ошибки типов выявляются на этапе **компиляции (Compile-time)** — ваша IDE (VS Code) подсветит ошибку красным еще до того, как вы запустите тест [1.3].

### Главные плюсы TS для автоматизатора:

1.  **Умное автозаполнение (IntelliSense):** Когда вы пишете методы страниц (Page Objects), IDE сама подсказывает, какие элементы и методы есть у класса, избавляя вас от необходимости постоянно заглядывать в другие файлы.
2.  **Безопасный рефакторинг (Safe Refactoring):** Если вы переименуете селектор или метод в одном Page Object, TS мгновенно подсветит ошибки во всех 500 файлах тестов, которые его используют [1.3].
3.  **Строгие типы тестовых данных (Typed Test Data):** Вы можете жестко описать форму (контракт) ваших JSON-фикстур и API-ответов [1.3]. Если бэкенд изменит структуру ответа, ваши тесты моментально укажужат на несоответствие.

---

## 2. Как устроена компиляция в TypeScript (Transpilation)

Браузеры и Node.js не умеют выполнять TypeScript напрямую [1.3]. Код на TS должен быть переведен (транспилирован) в чистый стандартный JavaScript [1.3].
[ Тест на TS (.ts) ] ──────► [ Компилятор TypeScript (tsc) ] ──────► [ Тест на JS (.js) ] ──────► [ Выполнение в Node.js ]

### Как это происходит в автотестах (On-the-Fly Compilation):

В отличие от веб-разработки, где проекты компилируют в физические файлы в папку `dist/` перед деплоем, современные тестовые раннеры компилируют тесты **на лету (в оперативной памяти)** [1.3]:

- **Playwright:** Нативно поддерживает TypeScript из коробки [1.3]. Вы просто запускаете команду `npx playwright test`, и Playwright сам быстро переводит TS-код в память с помощью сверхбыстрого сборщика `esbuild` [1.3].
- **Cypress:** Тоже нативно поддерживает TS, компилируя его на лету с помощью встроенного Webpack/Vite препроцессора [1.3].

Тем не менее, для работы автозаполнения в вашей IDE и правил проверки типов вам обязательно нужен файл **`tsconfig.json`** [1.3].

---

## 3. Разбор конфигурации `tsconfig.json` для AQA

Файл `tsconfig.json` — это главный конфигуратор настроек TypeScript в вашем проекте [1.3]. Вот эталонный конфиг, оптимизированный под современные стандарты автоматизации (Playwright, Cypress, Node.js v20+) [1.3]:

````json
{
  "compilerOptions": {
    /* Окружение и цель */
    "target": "ES2022",                          // В какой стандарт JS компилировать (ES2022 полностью поддерживается Node.js v18+)
    "module": "NodeNext",                        // Модульная система для поддержки современных ESM импортов (import/export)
    "moduleResolution": "NodeNext",              // Как искать файлы и сторонние QA библиотеки
    "lib": ["ES2022", "DOM"],                    // Добавляет типы встроенных библиотек JS и DOM-типы браузера (для локаторов)

    /* Строгость проверок */
    "strict": true,                              // Включает максимальную строгость проверок (самый безопасный режим)
    "noImplicitAny": true,                       // Запрещает переменным неявно принимать тип 'any' (заставляет писать типы вручную)
    "strictNullChecks": true,                    // Запрещает использовать переменные, которые могут быть null/undefined, без проверки

    /* Совместимость */
    "esModuleInterop": true,                     // Позволяет импортировать CommonJS модули как ESM (например, import lodash from 'lodash')
    "resolveJsonModule": true,                   // Разрешает напрямую импортировать JSON-файлы с автозаполнением их полей!
    "skipLibCheck": true,                        // Отключает проверку типов внутри папки node_modules (ускоряет запуск тестов на 80%)
    "forceConsistentCasingInFileNames": true,    // Защищает от ошибок регистра имен файлов при работе в разных ОС (Mac / Windows / Linux)

    /* Сборка */
    "noEmit": true                               // Запрещает компилятору сохранять .js файлы на диск (так как раннеры запускают тесты в памяти)
  },
  "include": [
    "src/**/*.ts",                               // Где лежат ваши Page Objects и утилиты
    "tests/**/*.ts"                              // Где лежат ваши файлы тестов
  ],
  "exclude": [
    "node_modules"                               // Никогда не проверять сторонние библиотеки
  ]
}
4. Ключевые настройки для AQA, которые нужно знать наизусть:
resolveJsonModule: true — Без этой настройки вы не сможете импортировать JSON-файлы тестовых данных (фикстуры) напрямую [1.3]. С ней вы получаете умные подсказки п�� полям вашего JSON прямо в коде тестов [1.3]!
skipLibCheck: true — В папке node_modules лежат гигабайты чужого кода [1.3]. Если не отключить их проверку, компилятор TypeScript будет тратить драгоценные минуты при каждом запуске ваших тестов, проверяя типы в чужих библиотеках [1.3].
strict: true — Заставляет вас писать надежный, чистый код. Включает проверку на null и undefined (чтобы вы случайно не попытались кликнуть по элементу, которого может не быть на странице) [1.3].
````
