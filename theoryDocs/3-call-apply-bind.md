# 📘 День 3: Контекст Выполнения (Execution Context) и Методы Привязки (`.call()`, `.apply()`, `.bind()`)

Сегодня мы изучим, как именно движок JavaScript управляет памятью и контекстом в момент запуска кода, и детально разберем методы управления им.

---

## 1. Контекст Выполнения (Execution Context) — Фундамент движка JS

Каждый раз, когда в JavaScript выполняется какой-либо код, он выполняется внутри специального виртуального окружения, которое называется **Контекст Выполнения (Execution Context, EC)**.

[ Global Execution Context ] (Создается один раз при старте программы)
▲
│ (Call Stack пушит новые контексты при вызове функций)
[ Function Execution Context ] (Создается каждый раз при запуске функции)

Движок JavaScript создает контексты выполнения и управляет ими с помощью структуры данных **Стек Вызовов (Call Stack)**.

### Фазы жизни Контекста Выполнения:

Любой контекст выполнения проходит через **две фазы**:

1.  **Фаза Создания (Creation Phase):**
    - Создается **Лексическое Окружение (Lexical Environment)**.
    - Переменные регистрируются в памяти и инициализируются значением `undefined`, а функции загружаются в память полностью (это и есть механизм поднятия — **Hoisting**).
    - Создается **Цепочка Областей Видимости (Scope Chain)**.
    - **Определяется значение `this`** для этого контекста.
2.  **Фаза Выполнения (Execution Phase):**
    - Движок выполняет код построчно, присваивая переменным их реальные значения из кода.

## 2. Карта поиска `this` (Decision Tree)

Чтобы безошибочно определить, чему равен `this` в любой строчке кода, используйте этот алгоритм. Задайте себе 4 вопроса по порядку:

              1. Функция вызвана с оператором "new" (new MyClass())?
                               │
                  ├─── YES ───► this = новый созданный экземпляр класса
                  │
                  └─── NO
                       │
              2. Функция вызвана через .call(), .apply() или .bind()?
                               │
                  ├─── YES ───► this = объект, явно переданный первым аргументом
                  │
                  └─── NO
                       │
              3. Функция вызвана на объекте (например, obj.myMethod())?
                               │
                  ├─── YES ───► this = объект слева от точки (obj)
                  │
                  └─── NO
                       │
              4. Это стрелочная функция (Arrow Function)?
                               │
                  ├─── YES ───► this = заимствуется из родительского окружения (Lexical Scope)
                  │
                  └─── NO  ───► Strict Mode: this = undefined
                                Sloppy Mode: this = global (window / global)

## 3. Явная Привязка: Различия `.call()`, `.apply()` и `.bind()`

Когда нам нужно жестко продиктовать JavaScript, какой именно объект должен стать контекстом `this`, мы используем три встроенных метода.

### 📞 Метод `.call()` — "C" для Comma-separated (Разделенные запятой)

Вызывает функцию **мгновенно**, передавая аргументы по одному через запятую.

- **Синтаксис:** `fn.call(thisArg, arg1, arg2, ...)`

### 📐 Метод `.apply()` — "A" для Array / Arguments (Массив аргументов)

Вызывает функцию **мгновенно**, но принимает все аргументы в виде одного единого массива.

- **Синтаксис:** `fn.apply(thisArg, [argsArray])`

```javascript
// Пример для сравнения .call() и .apply()
const runner = { name: "Playwright" };

function logTestResult(version, speed) {
  console.log(`${this.name} v${version} runs ${speed}!`);
}

// Вызовы приведут к одному результату:
logTestResult.call(runner, "1.40", "fast");       // Передаем через запятую
logTestResult.apply(runner, ["1.40", "fast"]);    // Передаем массивом
🔗 Метод .bind() — "B" для Bound / Blocked (Связанный)
НЕ вызывает функцию мгновенно. Вместо этого он возвращает новую функцию, у которой контекст this намертво заблокирован. Мы можем вызвать эту функцию позже.

Синтаксис: const boundFn = fn.bind(thisArg, presetArg1, presetArg2)
🛠️ Практические ловушки (Pitfalls) для Senior AQA
Ловушка А: Потеря контекста при передаче коллбеков в логи
Когда вы передаете метод страницы Page Object (POM) в качестве обертки для красивых логов (например, в test.step в Playwright или cy.then в Cypress), контекст теряется, превращая вызов в обычную функцию, где this становится undefined.

javascript


class LoginPage {
  constructor(page) { this.page = page; }
  async fillForm() { await this.page.fill('#input', 'value'); }
}

const loginPage = new LoginPage(page);

// ❌ УПАДЕТ: Метод оторван от объекта, inside test.step 'this' станет undefined
await test.step("Заполнение формы", loginPage.fillForm);

// ✅ РЕШЕНИЕ 1: Обернуть в стрелочную функцию (Lexical scope сохранит контекст)
await test.step("Заполнение формы", () => loginPage.fillForm());

// ✅ РЕШЕНИЕ 2: Явно привязать контекст через .bind()
await test.step("Заполнение формы", loginPage.fillForm.bind(loginPage));
Ловушка Б: Использование Arrow Functions в хуках Mocha / Cypress
Если в тестах Cypress/Mocha вам нужно использовать общие переменные через контекст this (алиасы), стрелочные функции полностью заблокируют эту возможность.

javascript


// ❌ НЕПРАВИЛЬНО: Стрелочная функция заимствует глобальный this (undefined)
beforeEach(() => {
  cy.fixture('users').as('testUser');
});

it('test', () => {
  console.log(this.testUser); // ❌ Ошибка: Cannot read properties of undefined
});

// ✅ ПРАВИЛЬНО: Обычная функция позволяет Mocha динамически привязать контекст
beforeEach(function() {
  cy.fixture('users').as('testUser');
});

it('test', function() {
  console.log(this.testUser); // ✅ Работает!
});
```

Вам не нужно гадать или биндить всё подряд. В 99% случаев в реальном коде автотестов потеря контекста происходит в двух конкретных ситуациях. Запомните их, и вы всегда будете знать, когда нужно привязывать контекст.

Ситуация 1: Передача метода объекта в качестве коллбека (Callback)
Это абсолютный рекордсмен по потере контекста.

Как понять, что это она:
Если вы берете метод какого-то объекта или класса (например, loginPage.submit) и передаете его внутрь другой функции как аргумент, чтобы та запустила его позже.

Пример в Playwright (тест-шаги):

javascript

// ❌ КОНТЕКСТ ПОТЕРЯЕТСЯ!
// Метод fillForm оторвется от loginPage и запустится "сиротой" внутри test.step
await test.step("Заполнить форму", loginPage.fillForm);
Как вы это поймете: Тест упадет с ошибкой Cannot read properties of undefined (reading 'page') (потому что внутри метода this стал undefined, и он не может прочитать this.page).
Решение: Использовать .bind():
javascript

await test.step("Заполнить форму", loginPage.fillForm.bind(loginPage));
Пример с обработчиками событий или очередями:
Если вы передаете метод в setTimeout, setInterval или сторонние библиотеки-планировщики.

javascript

// ❌ ПОТЕРЯ: setTimeout вызовет click просто как функцию
setTimeout(loginButton.click, 1000);

// ✅ РЕШЕНИЕ: Привязать контекст
setTimeout(loginButton.click.bind(loginButton), 1000);
Ситуация 2: Заимствование методов (Method Borrowing)
Это архитектурный паттерн, когда у вас есть готовая классная функция, но она лежит в другом объекте, и вы хотите "одолжить" её на один раз для своего объекта [1.2].

Как понять, что это она:
Вам нужно выполнить действие, но вы не хотите дублировать код и копипастить функцию к себе в объект [1.2].

Пример в UI-тестах (White-label приложения):
У вас есть два разных класса страниц: BrandAPage и BrandBPage. У них разные селекторы, но одинаковое сложное действие (например, выбор элемента из выпадающего списка).
Вы выносите это действие в отдельный хелпер Helper, у которого нет своего page, он ожидает его из this:
javascript

// Хелпер ожидает, что у контекста будет 'this.page'
const dropdownHelper = function(selector, value) {
await this.page.click(selector);
}
Внутри класса BrandAPage вы "одалживаете" этот метод на один раз с помощью .call():
javascript

class BrandAPage {
constructor(page) { this.page = page; }

async selectCountry() {
// ✅ РЕШЕНИЕ: Одалживаем хелпер и передаем BrandAPage (this) в качестве контекста
await dropdownHelper.call(this, "#country", "USA");
}
}
Золотое правило для самопроверки (Cheat Sheet):
Каждый раз, когда вы видите в коде конструкцию, где метод объекта передается БЕЗ точки и БЕЗ круглых скобок (то есть просто по ссылке), задайте себе вопрос:

"Будет ли эта функция внутри использовать слово this?"

Если ДА (например, внутри метода написано this.page.click) — контекст гарантированно потеряется! Вам нужно использовать .bind() [1.2].
Если НЕТ (метод просто делает математические вычисления или выводит чистый текст без this) — контекст не нужен, можно передавать просто так.
