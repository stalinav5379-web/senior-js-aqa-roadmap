# 📘 День 30: Интерфейсы (`interface`) и Типы (`type`) в TypeScript

Сегодня мы разберем, как описывать сложные структуры данных, контракты API-запросов и конфигурации тестов, используя два главных инструмента TypeScript: **Интерфейсы (Interfaces)** и **Алиасы типов (Type Aliases)**. Мы также изучим их сходства, критические различия и лучшие практики использования в AQA.

---

## 1. Что такое Type Alias и Interface?

Оба этих инструмента служат одной цели — они создают именованные «чертежи» (схемы) для ваших объектов, чтобы компилятор мог строго следить за их структурой.

### Алиас типа (Type Alias)

Создает новое имя (псевдоним) для любого типа данных: объекта, примитива, объединения (Union) или массива [1.1].

- **Синтаксис:** использует ключевое слово `type` и знак присваивания `=` [1.1].

```typescript
type UserRole = "admin" | "editor" | "guest"; // Литеральный тип
type UserId = string | number;               // Union-тип

type TestUser = {
  id: UserId;
  username: string;
  role: UserRole;
};

Интерфейс (Interface)
Описывает исключительно форму объектов (объекты, классы, функции) [1.1]. Интерфейсы не могут описывать примитивы или простые Union-типы напрямую [1.1].

Синтаксис: использует ключевое слово interface без знака = [1.1].
typescript


interface WebButton {
  selector: string;
  label: string;
  click(): void; // Описание метода внутри объекта
}

2. Наследование и Расширение (Extending Types)
В автотестах мы постоянно расширяем структуры данных (например, базовый пользователь расширяется до админа, у которого есть дополнительные права).

Расширение интерфейсов через extends [1.1]
Интерфейсы используют классический, интуитивно понятный синтаксис наследования ООП [1.1].

typescript


interface BaseUser {
  id: string;
  email: string;
}

// Администратор наследует все поля BaseUser и добавляет свое
interface AdminUser extends BaseUser {
  adminToken: string;
  deleteUser(userId: string): void;
}
Расширение типов через Пересечения (Intersection Types &)
Типы расширяются путем объединения (пересечения) через амперсанд & [1.1].

typescript


type BaseCustomer = {
  id: string;
  name: string;
};

// Объединяем свойства BaseCustomer и новые свойства в один тип
type PremiumCustomer = BaseCustomer & {
  discountRate: number;
};
3. Ключевые различия: type vs interface [1.1]
Хотя они кажутся очень похожими, между ними есть три фундаментальных различия:

Характеристика	interface	type
Что может описывать?
- interface: Только объекты, классы и функции [1.1]
- type: Любые типы (примитивы, Union, массивы, кортежи) [1.1]
Синтаксис расширения?
-  interface: Использует ключевое слово extends [1.1]
- type: Использует пересечение через оператор & [1.1]
Слияние объявлений (Declaration Merging)?
- interface: 	✅ Да. Если объявить два интерфейса с одним именем, они автоматически сольются в один [1.1]
- type: ❌ Нет. Повторное объявление типа с тем же именем вызовет ошибку компиляции [1.1]

Что такое Слияние Объявлений (Declaration Merging)? [1.1]
Если вы объявите два одинаковых интерфейса в разных частях проекта, TypeScript объединит их свойства в одну структуру [1.1].

typescript


interface PageConfig {
  baseUrl: string;
}

// Объявляем в другом файле:
interface PageConfig {
  timeout: number;
}

// Результат: TypeScript видит PageConfig как единый объект:
// { baseUrl: string; timeout: number; }
Этот прием очень полезен для расширения глобальных типов сторонних библиотек (например, когда вы хотите добавить кастомные методы в интерфейс Cypress или Playwright).

4. Использование в AQA: Типизация API-Контрактов
В API-автоматизации мы используем интерфейсы для строгого описания контрактов запросов и ответов (Request/Response Payloads). Это гарантирует, что тесты не отправят невалидные JSON на бэкенд [1.1, 1.3].

typescript


// Описываем вложенную сущность
interface Address {
  city: string;
  zipCode: string;
}

// Описываем контракт API-запроса на создание пользователя
interface CreateUserRequest {
  username: string;
  email: string;
  address?: Address; // Вложенный опциональный интерфейс [1.1]
}

// Описываем контракт ответа сервера
interface CreateUserResponse {
  id: number;
  createdAt: string;
  status: "success" | "pending"; // Литеральный союз [1.1]
}
5. Золотые правила выбора: Что использовать? [1.1]
В профессиональном сообществе принято придерживаться следующих правил [1.1]:

По умолчанию всегда используйте interface для описания структуры объектов, Page Objects, API-запросов и ответов [1.1]. Его синтаксис наследования extends более читаем и производителен при компиляции [1.1].
Используйте type, когда вам нужно:
Создать Union-типы (например, type Env = "dev" | "stage").
Создать псевдоним для примитива (например, type Token = string).
Описать сложные кортежи (Tuples) [1.1].
```

Постановка задачи:
Вам нужно полностью самостоятельно описать типы и интерфейсы для системы обработки заказов интернет-магазина [1.1].

Создайте Union Type PaymentMethod (Алиас типа):

Он должен принимать строго три текстовых значения: "credit_card", "crypto" или "paypal".
Создайте Interface BaseOrder (Базовый заказ):

id: строка (обязательно).
amount: число (обязательно).
currency: строка (обязательно, например, "USD").
paymentMethod: тип PaymentMethod, который вы создали на шаге 1 [1.1].
Создайте Interface CardOrder (Заказ по карте):

Он должен наследовать все свойства от BaseOrder [1.1].
Дополнительное свойство cardNumber: строка (обязательно).
Дополнительное свойство cardHolder: строка (обязательно).
Создайте Interface CryptoOrder (Крипто-заказ):

Он должен наследовать все свойства от BaseOrder [1.1].
Дополнительное свойство walletAddress: строка (обязательно).
Дополнительное свойство txHash: строка (опционально, так как транзакция может быть еще не подтверждена) [1.1].
Напишите функцию processPayment:

Она должна принимать один параметр order [1.1].
Типом параметра order может быть либо CardOrder, либо CryptoOrder (используйте Union CardOrder | CryptoOrder) [1.1].
Функция ничего не возвращает (void).
Внутри функции напишите логику:
Если order.paymentMethod === "credit_card", выведите в консоль: "Processing card payment of X USD for Y. Card: Z".
Если order.paymentMethod === "crypto", выведите в консоль: "Processing crypto payment of X USD. Wallet: W".
(Подсказка: чтобы достучаться до уникальных свойств вроде cardNumber или walletAddress внутри функции, TypeScript потребует от вас сначала проверить тип платежа через if (order.paymentMethod === ...)).
