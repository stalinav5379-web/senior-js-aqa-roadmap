# 📘 День 1: Области видимости, Переменные (let, const, var) и Поднятие (Hoisting)

В JavaScript есть три ключевых слова для создания переменных: `var` (старый стандарт до 2015 года), `let` и `const` (современный стандарт ES6).

---

## 1. Область видимости (Scope)

Область видимости определяет, где ваша переменная "живет" и откуда к ней можно получить доступ.

*   **`var` имеет функциональную область видимости (Function Scope):**
    Если переменная создана внутри функции с помощью `var`, она видна везде внутри этой функции. Но если она создана внутри блока `if` или цикла `for`, она «вываливается» наружу и становится видна за пределами этого блока.
*   **`let` и `const` имеют блочную область видимости (Block Scope):**
    Переменная «живет» строго внутри фигурных скобок `{ }`, где она была объявлена (будь то функция, цикл `for` или блок `if`). Снаружи этих скобок её не существует.

### Пример (почему `var` — это опасно):
```javascript
if (true) {
  var age = 30;
  let name = 'Alina';
}
console.log(age);  // Выведет: 30 (var просочился наружу!)
console.log(name); // Ошибка! ReferenceError: name is not defined (let остался внутри)

2. Переопределение и переприсваивание
var: позволяет повторно объявлять ту же самую переменную (код var x = 1; var x = 2; выполнится без ошибок, что часто приводит к случайной перезаписи данных в больших тест-фреймворках).
let: позволяет менять значение (переприсваивать), но выдаст ошибку, если вы попытаетесь объявить её заново в той же области видимости.
const: не позволяет ни переприсваивать значение, ни объявлять переменную заново.
⚠️ Важно для AQA: Если в const записан объект или массив, мы можем менять его внутренности (добавлять ключи, удалять свойства, пушить элементы), но не можем заменить объект целиком.

javascript


const user = { name: 'Alina' };
user.name = 'Stas';      // МОЖНО! Внутренности объекта менять разрешено.
user = { name: 'Alex' }; // ОШИБКА! Заменить объект целиком нельзя.
3. Поднятие (Hoisting) и Временная мертвая зона (TDZ)
Движок JavaScript выполняет код в два прохода. На первом проходе он сканирует код и находит все переменные.

Для var: переменная «поднимается» (hoisted) в самый верх своей области видимости и инициализируется значением undefined. Мы можем обратиться к ней до того, как объявили в коде.
Для let и const: они тоже «поднимаются», но не инициализируются ничем. Время от начала выполнения области видимости до строки, где объявлена переменная let/const, называется Временной мертвой зоной (Temporal Dead Zone, TDZ). Если обратиться к ним в этой зоне — будет ошибка.
javascript


console.log(a); // Выведет: undefined (var поднялся и равен undefined)
var a = 5;

console.log(b); // ОШИБКА! ReferenceError: Cannot access 'b' before initialization (b в TDZ!)
let b = 10;

Задача «Странный цикл»
Представьте, что мы пишем тест, который кликает по очереди на 3 кнопки на сайте. Мы хотим сымитировать это задержкой setTimeout (асинхронное действие).

javascript


// Тест со старым var
function runTestWithVar() {
  for (var i = 1; i <= 3; i++) {
    setTimeout(function() {
      console.log('Клик по кнопке номер (с var): ' + i);
    }, 100);
  }
}

// Тест с современным let
function runTestWithLet() {
  for (let i = 1; i <= 3; i++) {
    setTimeout(function() {
      console.log('Клик по кнопке номер (с let): ' + i);
    }, 100);
  }
}

console.log('Запуск теста с var:');
runTestWithVar();

// Запустим второй тест чуть позже, чтоб логи не перемешались
setTimeout(() => {
  console.log('\nЗапуск теста с let:');
  runTestWithLet();
}, 500);
