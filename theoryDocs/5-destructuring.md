## 1. Деструктуризация (Destructuring) — Чистое извлечение данных

**Деструктуризация (Destructuring)** — это особый синтаксис в ES6, который позволяет «распаковывать» значения из массивов или свойства из объектов напрямую в отдельные переменные одной строкой [3].

### Деструктуризация объектов (Object Destructuring)

#### ❌ До ES6 (Многократные лишние ссылки на объект):

```javascript
function printTestReport(testResult) {
  const name = testResult.name;
  const status = testResult.status;
  const duration = testResult.duration;

  console.log(`Тест ${name} завершился со статусом ${status} за ${duration}мс`);
}
После ES6 (Лаконично в одну строчку):
javascript


function printTestReport(testResult) {
  const { name, status, duration } = testResult; // Распаковка!
  console.log(`Тест ${name} завершился со статусом ${status} за ${duration}мс`);
}
🌟 Сеньорный подход: Деструктуризация параметров (Parameter Destructuring)
Мы можем распаковывать объект прямо на лету, прямо в сигнатуре (параметрах) функции [3]. Это сразу показывает читающему код разработчику, какие именно поля требуются функции для работы [3].

javascript


// Распаковка происходит прямо в круглых скобках функции:
function printTestReport({ name, status, duration }) {
  console.log(`Тест ${name} завершился со статусом ${status} за ${duration}мс`);
}
Деструктуризация с дефолтными значениями (Default Values)
Если свойства в объекте нет (оно undefined), мы можем безопасно задать дефолтное значение-заглушку прямо во время извлечения [3].

javascript


const browserConfig = { headless: true };

// Если timeout отсутствует в объекте, он автоматически примет значение 30000
const { headless, timeout = 30000 } = browserConfig;

console.log(timeout); // 30000
Переименование переменных при деструктуризации (Renaming)
Иногда имена свойств в объекте слишком длинные или конфликтуют с существующими переменными. Мы можем переименовать их прямо при извлечении с помощью синтаксиса : [3].

javascript


const response = { id: "USR_1092", data: "Alina" };

// Извлекаем 'id', но записываем в переменную 'userId'.
// Извлекаем 'data', но записываем в переменную 'username'.
const { id: userId, data: username } = response;

console.log(userId);   // "USR_1092"
console.log(username); // "Alina"
2. Оператор Развертывания (Spread Operator ...)
Оператор Spread (дословно: распространение/разворачивание) «распаковывает» элементы массива или свойства объекта, распределяя их внутри нового окружения [3]. Его главная цель — обеспечение иммутабельности (Immutability) при создании копий и слиянии [3].

💡 Как его узнать: Оператор Spread ВСЕГДА стоит в правой части выражения (после знака =) или при передаче аргументов в функцию [3].

Использование с объектами (Копирование без мутаций):
javascript


const devConfig = { env: "dev", port: 3000 };

// Создаем новый объект, копируем туда все свойства devConfig и меняем 'env':
const stagingConfig = { ...devConfig, env: "staging" };

console.log(devConfig.env);     // "dev" (Оригинал не пострадал!)
console.log(stagingConfig.env); // "staging"
Использование с массивами (Быстрое слияние):
javascript


const smokeTests = ["login.spec.js", "dashboard.spec.js"];
const regressionTests = ["billing.spec.js"];

// Склеиваем два массива и добавляем новый элемент в одну строчку:
const allTests = [...smokeTests, ...regressionTests, "teardown.js"];

console.log(allTests);
// ["login.spec.js", "dashboard.spec.js", "billing.spec.js", "teardown.js"]
3. Оператор Сбора (Rest Operator ...)
Выглядит точно так же (...), но делает противоположную вещь: он собирает (упаковывает) оставшиеся элементы в один массив или объект [3].

💡 Как его узнать: Оператор Rest ВСЕГДА стоит в левой части выражения (при объявлении переменных при деструктуризации) или в списке параметров функции [3].

Сбор параметров функции (Вместо устаревшего arguments)
Заменяет собой небезопасный и неудобный псевдомассив arguments, предоставляя полноценный, настоящий массив [3].

javascript


// Собираем все переданные аргументы в массив 'suites'
function runSuites(...suites) {
  // 'suites' — это полноценный массив, у него есть метод .forEach()!
  suites.forEach(suite => console.log(`Запуск сюиты: ${suite}`));
}

runSuites("Smoke", "Regression", "E2E");
Паттерн «Исключение свойств» (Omit / Exclusion Pattern)
С помощью Rest мы можем забрать из объекта конкретные свойства, а все остальные — автоматически сгруппировать в новый чистый объект [3].

Это мега-популярный паттерн в AQA для очистки логов от чувствительных данных (пароли, токены) перед выводом в консоль [3].

javascript


const userPayload = {
  id: "992",
  username: "QA_Master",
  password: "SuperSecretPassword123", // Конфиденциально!
  email: "qa@test.com"
};

// Извлекаем password отдельно, а всё остальное собираем в объект publicData
const { password, ...publicData } = userPayload;

console.log(publicData);
// Output: { id: "992", username: "QA_Master", email: "qa@test.com" }
// (Теперь publicData можно безопасно логгировать!)
```
