# 📘 День 6: Динамический Модуль Конфигурации (Dynamic Configuration Module)

Сегодня мы объединим знания о переменных, объектах, глубоком замораживании и деструктуризации, чтобы построить промышленный, безопасный конфигуратор тестового окружения.

---

## 1. Зачем нужен выделенный модуль конфигурации?

В плохих фреймворках автоматизации инженеры часто обращаются к переменным окружения (`process.env.MY_VAR`) напрямую из классов страниц (Page Objects) или файлов тестов.

### Почему обращение к `process.env` напрямую — это антипаттерн (Anti-Pattern):

1.  **Отсутствие типизации:** Все переменные из `process.env` всегда прилетают в виде обычных строк (`string`). Если вам нужен порт базы данных как число (`5432`) или флаг headless-режима как булево значение (`true`), вам придется вручную преобразовывать типы в каждом тесте.
2.  **Тихие падения (Silent Failures):** Если кто-то запустит тесты в CI/CD и забудет указать критический токен авторизации, тесты начнут выполняться, потратят время и упадут в случайных местах с невнятными ошибками вроде `401 Unauthorized` или `Cannot read property of undefined`.
3.  **Отсутствие защиты (No Immutability):** Любой тест может случайно перезаписать глобальный `process.env` во время выполнения, сломав параллельный запуск других тестов.

---

## 2. Архитектура Сеньорного Конфигуратора (Framework Configuration Design)

Качественный конфигуратор строится по принципу **Fail-Fast (Упасть как можно раньше)**. Если конфигурация собрана неверно — проект должен упасть с понятной ошибкой на первой секунде старта, еще до открытия браузера.

Конфигуратор состоит из 4 шагов:
Определение целевого стенда (TARGET_ENV: local, staging, prod)
│
▼
Загрузка базовых статических настроек для этого стенда (Base Config)
│
▼
Наложение секретов и перегрузок из process.env (Environment Overrides)
│
▼
Проверка обязательных полей (Validation) & Глубокая заморозка (Deep Freeze)

---

## 3. Нативная работа с `.env` в Node.js (Без внешних библиотек)

Раньше для работы с файлами настроек `.env` все устанавливали стороннюю библиотеку `dotenv`. Но начиная с современных версий Node.js (v20 LTS), поддержка `.env` встроена в движок **нативно**.

Вы можете запускать свои тесты, передавая флаг конфигурации прямо в команду запуска:

```bash
node --env-file=.env my_test.js
Движок Node.js сам прочитает файл .env, распарсит его и автоматически запишет все ключи в объект process.env.

4. Глубокая заморозка (Deep Freeze) — Защита от мутаций
Чтобы гарантировать, что ни один тест не сможет динамически поменять адрес стенда (config.baseUrl = ...) во время выполнения, конфигуратор прогоняет готовый объект через рекурсивную функцию глубокой заморозки.

javascript


function deepFreeze(object) {
  // Получаем ключи первого уровня
  Object.keys(object).forEach(name => {
    const value = object[name];
    // Если свойство является вложенным объектом — замораживаем его рекурсивно!
    if (value && typeof value === 'object') {
      deepFreeze(value);
    }
  });
  // Замораживаем текущий уровень объекта
  return Object.freeze(object);
}


```
